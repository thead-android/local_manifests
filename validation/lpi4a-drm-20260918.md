# LPi4A DRM backports — 2026-09-18

Kernel source: `d867ce4aa96d8ec1bfab8469e0e5b7dcd18a278a`.
Previous published source: `5e223c0a317c683197934ab5e8160082a061033e`.
Reference: RevyOS `revyos/7.1.y`, `acbd3c3f6d7e5610b7343dd55224bfe5e079c7e9`.
Upstream authorship is retained; existing LPi4A changes are preserved rather
than replacing either driver directory wholesale.

## Included changes

- Correct PowerVR DEV_QUERY returned lengths.
- Make firmware trace parameter operations private to their translation unit.
- Correct user-array input/output strides and per-element padding.
- Reject invalid GPU VM context handles instead of dereferencing NULL.
- Serialize GPU VM mapping against concurrent mapping/lookups/unmapping.
- Encode Verisilicon cursor offsets into their register bit fields.
- Avoid double clipping cursor framebuffer addresses; use the common DMA
  helper for cursor and primary planes. Retain the existing clipped-address
  helper for LPi4A's additional overlay plane.

Existing paired-job/CCCB fixes, private GEM large-page allocations, tracing,
display wake, DSI and overlay support remain in place.

## Validation actually completed

Built against the accepted LPi4A kernel configuration and prepared output with
the same kernel Clang r596125. Kernel module version checks remained enabled;
no forced load, signature bypass, optimizer or runtime-check disablement.

Kbuild's compiler capability probes must see the selected GCC installation.
On the test build host, explicit selection was placed in the compiler command:
`CC='clang --gcc-install-dir=/usr/lib/gcc-cross/riscv64-linux-gnu/14'`.
Putting it only in KCFLAGS had caused warning-driven probe failures and missing
`-mno-relax`; that rejected build was discarded. Accepted modules were checked
for unsupported `R_RISCV_ALIGN` relocations before loading.

Modules were tested separately on the real LPi4A, with loaded GNU build IDs
verified. Required existing module parameters were preserved:
`powervr exp_hw_support=1`, `verisilicon-dc lpi4a_dsi0=1`.

PowerVR passed:

- Query lengths, oversized zero-padded inputs and undersized rejection.
- Static-data array values/padding at strides 24, 32 and 40 bytes.
- Invalid VM context handle correctly returns EINVAL.
- Four threads sharing one VM completed 6000 map/unmap pairs.
- 1080x2160 EGL drawing of solid, texture and two AA-rounded workloads:
  all four full-frame pixel hashes matched the preceding baseline.

Verisilicon passed:

- 1080x2160 DSI modeset.
- Cursor commits at (32,32), (-16,32), (32,-16), (-32,-32), (1064,2144), (0,0).
- Android compositor/SystemUI restart with both display IDs enumerated.

Both original modules were restored after testing; no system partition or
bootloader was written. Existing firmware image hashes therefore remain valid.

These are bounded module regression tests, **not** a new full-image/cold-boot
acceptance, photographic verification of cursor clipping, or proof that all
earlier whole-system hangs are fixed. No rendering speedup or GLES3 conformance
is claimed. The older immutable `lpi4a-20260918` manifest tag is unchanged;
the `android17` branch carries this new source revision.
