# Mesa and C910 compiler update — 2026-09-19

## Inputs

- Mesa runtime source: `2d5c5aa8da13f1574f6653e52d2a33421003aabb`, based on
  upstream `9acc3e3aceb6addc499ee74b62021ee8e17ec34e` (26.3 development).
- Android build integration: exact revision/tree in `source-lock.json`.
- Clang/LLD/llc source: `217e452c13201d5a78eca139f46d74aa1220568e`.
- Compiler asset: `clang-c910-llvm22-mesa-20260919`, SHA256
  `9e424ee9ae422927dea8e3666f34b333826348b81730e93a13e013005cb0fe28`.
- Rust remains `1.93.1-c910-llvm22`; these new LLVM fixes are **not** claimed
  to be included in Rust's backend.

The compiler update preserves the archived correctness layers and historical
VL1/VL2 implementation, and fixes fixed/scalable predicate conversions and
subvector extraction for C910's MLEN-spaced vector predicates. No vector ISA
extension or global optimization is disabled to avoid the failing tests.
LLD was linked with the same corrected RISC-V code generator as Clang so
ThinLTO also receives the fix.

## Android build integration

Soong files are generated using Meson's unmodified PR 15462 converter,
revision `ef04015b87f27b6ce62e754fdbdddf4a4969fa1a`, with the Mesa-side script
`src/gfxstream/hermetic/android/regenerate_lpi4a.py` and checked-in configuration.
The legacy Android Make integration is retained as `android/Android.legacy.mk`
to avoid AOSP 17's Android.mk denylist.

The optional `imagination-android-precompiled` path supplies generated GPU
shader C/H source from the successful standalone build, with checksums and
provenance in `src/imagination/android-precompiled`. It is selected by the
Soong configuration; normal Meson builds still generate these sources.
Mesa's no-LTO policy is preserved. Rust lint architecture selection is emitted
using the existing AOSP arch syntax rather than unsupported select properties.
Python generator aliases retain the upstream scripts without stale duplicated
content. PowerVR's supported `-Werror=pointer-arith` option is kept separate
from the converter's incorrectly selected MSVC compatibility flag group.
Three ineffective return-type qualifiers were removed in `pvr_dump.h` and
`pvr_arch_cmd_query.c` to satisfy the existing warning policy; no renderer
algorithm was changed. Missing CSB, shader-statistics, PCO and Git-ID generated
header dependencies were added in Meson and regenerated into Soong.

AOSP module build **passed**: `m -j16 vulkan.powervr`, exit 0, with Mesa
`31c2c6edf3dafb78b4d0fb4af9399e1767d73d33` freshly checked out from GitHub and
the released C910 Clang/LLD. A separate container mounted the existing AOSP
dependencies read-only, overlaid only Mesa/the compiler view, and used a separate
output directory. This was not a full fresh sync/build of all AOSP projects.
The normal Soong `-O2` and C910 vector extensions remained enabled.

Installed module: `vendor/lib64/hw/vulkan.powervr.so`, ELF64 RISC-V,
SHA256 `614f0ceb3d12a17d1543b3314dfa2835e8a6963eada82e2e549b4b1e5a655fd5`.
This new Soong artifact is build-validated, not yet substituted on the board;
the earlier standalone runtime tests above used their separately identified
artifact. Build-script defaults select Ninja and the new compiler version.

## Limits

Notification-shade animation is still slow: measured reported frame medians
were approximately 113–137 ms in the new-driver runs. HDMI woke during testing;
these are not controlled DSI-only measurements or evidence of a precise
percentage speedup. Both physical outputs used client composition.

This update does not certify a full-system clean build, flash/cold boot,
long-term stability, CTS, or 60 fps. The separate perf guest-callback KCFI panic
and historical system stalls are not fixed by these compiler changes.
